# Foreground Gemma, background Qwen (#155)

> Reachy Mini is one embodied presence over two model lanes: the operator talks with Gemma — the foreground interlocutor that listens, sees, speaks and handles turn-taking — while Qwen follows the conversation in the background, reasons over longer horizons, operates tools, and injects compact thinking scopes through typed events. Long replies stream as cancellable chunks a human can interject over, attention gates the voice as well as the mind, perception arrives as compact fresh snapshots that never evict runtime facts, and the attention window is an operator knob.

## Audience

- The operator — and anyone in the room — holding a spoken conversation with Reachy Mini; secondarily the developers and mesh agents operating the embodiment layer via agent embody and its export feeds (issue #155)

## Before → After

- After: Asked what it can see, the robot answers from the latest perception snapshot; ambient speech outside attention produces no spoken reply; the attention window is tunable without a code edit; verbose image updates never displace runtime facts; Qwen follows the conversation in the background, acts through tools, and injects scopes — including authorized interjections — without owning the mouth; long answers start quickly, arrive in coherent chunks, stop cleanly when interrupted, and never resume stale queued speech (issue #155 acceptance scenarios)

## Why it matters

- Today speech, perception, runtime state and reasoning are loosely connected prompt inputs: the voice contradicts what the robot knows (#153), cheap perceptions evict valuable facts (#154), the ignored room still gets answered aloud (#149), and replies cannot be long or interrupted (#151) — symptoms of ONE architectural problem, the missing governed event-and-context model (issue #155 Problem section)

  - honesty: The audio a human hears traces only to the realtime floor rendering foreground output; no code path lets the worker model's text reach TTS or playback directly (asserted by test over the embody tool registry's voice path and the duplex client), and any Qwen influence on speech is visible as a typed event on the export feed

  - honesty: A test pins m<=n over ONE shared history (Gemma's window a strict suffix of Qwen's, both bounds in Limits), and a long conversation does not grow Gemma's per-call context without bound (a growth test over 100+ turns)
- Attention gates SPEECH, not only cognition: ambient speech outside the attention window produces no spoken response — ignore means ignore silently (issues #149 + #155 invariant 'Attention gates speech, not only cognition')

## Assumptions

- Talking with Gemma means the lobes realtime FLOOR speaks as Gemma: the reply text the operator hears is generated by lobes/realtime/`_floor.py` via the realtime service's `OPENAI_MODEL` setting (empty string default-routes at the gateway — lobes-cli lobes/realtime/`_settings.py`), not by either of the layer's own lanes; pointing that model at Gemma is deployment config plus, if wanted per-session, a small upstream ask
- ONE armed session per box remains the constraint: the t1 probe verified an ears-only session beside one ARMED session and deliberately never tested two armed sessions, and upstream `TTS_VOICE_CONCURRENCY` defaults to 1 (reachy/speech/`realtime_duplex.py` docstring) — the foreground/background split keeps exactly one armed conversational session, the layer's, beside the runtime's ears-only session
- Interjection reconciles with c2 and #155's never-silently-replaces-the-speaker invariant because the EVENT is Qwen's output while the SPEECH stays Gemma's: an interjection is the speakable face of a cognition scope (speakable=true plus priority and expiry), Gemma keeps the wording and the decision to speak, and c8's raw-reasoning ban applies to its content unchanged
- Cut detection keys on VAD-verified speech — the session's `speech_started` / committed-turn evidence (the floor already treats a committed turn as far stronger interruption evidence than a bare onset) — never raw loudness, so a cough or door slam does not cut the robot; and the said/unsaid TEXT split is byte-proportional in phase 1 (client-chunked whole-reply PCM: full text + delivered bytes known, alignment estimated) and becomes EXACT when phase 2's per-sentence semantic delivery lands
- Gemma is now named in TWO configs — the realtime service's `OPENAI_MODEL` (the voice) and the layer's `REACHY_EMBODY_SENSES_MODEL` (the clip asker): they are a documented PAIR that moves together or warns (a doctor/status check at plan time), or the voice and the perception lane silently run different models

## Decisions

- History ownership: the layer curates the canonical conversation history and pushes projections to the floor; lobes' server-side history is what the layer put there (resolves q1)
- Injection channel: conversation.item.create — the layer asks lobes for the parked conversation-item parity and deliberately widens its pinned send surface from three frame kinds to four (resolves q2)
- Chunking order: client-side cancellable chunk playback FIRST (no upstream dependency), the semantic per-sentence TTS delivery ask on lobes SECOND for earlier first speech (resolves q3)
- Window bounds: m=20 (Gemma) nested in n=60 (Qwen) over one history, plus ONE Qwen-maintained summary (compacted 21..60 + rolling >60 for Gemma); all bounds in Limits, m<=n pinned by test (resolves q4)
- Interjection scope: warm-only under base authorization; a separate explicit proactive level for cold; an interjection never opens the attention window (resolves q5)
- Worker voice tools: speak/harmonics remain but route through the interjection policy — unauthorized is a named drop, authorized becomes a typed event Gemma renders (resolves q6)
